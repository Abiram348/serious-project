## 1. Purpose

## 3. Model Specifications

### 3.1 User

The central identity model. Synced from Clerk via webhooks.

```prisma
model User {
  id        String   @id @default(cuid())
  clerkId   String   @unique
  email     String   @unique
  name      String?
  avatarUrl String?
  plan      String   @default("FREE")
  credits   Int      @default(100)
  createdAt DateTime @default(now())
  updatedAt DateTime @default(now())

  projects      Project[]
  subscriptions Subscription[]
  usageLogs     UsageLog[]

  @@map("users")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `id` | CUID | PK | Internal reference; never exposed to users |
| `clerkId` | String | Unique | Clerk's user ID; stable external identity |
| `email` | String | Unique | Contact + Stripe billing match |
| `name` | String? | — | Display name from Clerk profile |
| `avatarUrl` | String? | — | Clerk avatar or Gravatar fallback |
| `plan` | String | Default "FREE" | FREE, PRO, TEAM, ENTERPRISE |
| `credits` | Int | Default 100 | Legacy field; now superseded by UsageLog + Stripe |
| `createdAt` | DateTime | Default now | Audit |
| `updatedAt` | DateTime | Default now | Audit; should use `@updatedAt` |

**Indexes:**
- `clerkId` — UNIQUE (implicit)
- `email` — UNIQUE (implicit)

**Rules:**
- Do NOT delete `User` records. If Clerk user is deleted, soft-archive by setting `plan = "ARCHIVED"`.
- `updatedAt` should migrate to `@updatedAt` generator.

### 3.2 Project

A software project generated by the agent swarm.

```prisma
model Project {
  id            String   @id @default(cuid())
  userId        String
  name          String
  description   String?
  status        String   @default("PENDING")
  techStack     Json?
  sandboxId     String?
  previewUrl    String?
  previewStatus String?  @default("STOPPED")
  githubRepo    String?
  deployUrl     String?
  createdAt     DateTime @default(now())
  updatedAt     DateTime @default(now())

  user            User             @relation(fields: [userId], references: [id], onDelete: Cascade)
  agentRuns       AgentRun[]
  projectFiles    ProjectFile[]
  chatMessages    ChatMessage[]
  buildLogs       BuildLog[]
  usageLogs       UsageLog[]
  modelPreference ModelPreference?

  @@map("projects")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `id` | CUID | PK | Public in URLs |
| `userId` | String | FK → User.id | Ownership; cascade delete removes all project data |
| `name` | String | — | User-provided or AI-generated |
| `description` | String? | — | Original prompt; truncated to 2000 chars |
| `status` | String | Default "PENDING" | Lifecycle state machine |
| `techStack` | Json? | — | `{ frontend, backend, database, styling }` |
| `sandboxId` | String? | — | E2B sandbox identifier (planned) |
| `previewUrl` | String? | — | Live preview URL when running |
| `previewStatus` | String? | Default "STOPPED" | STOPPED, BUILDING, RUNNING, ERROR |
| `githubRepo` | String? | — | Exported repo URL |
| `deployUrl` | String? | — | Live deployment URL |

**Valid status values:**
- `PENDING` — Created, not yet started
- `PLANNING` — Supervisor running
- `IN_PROGRESS` — Agents generating files
- `REVIEWING` — Awaiting user review (future)
- `COMPLETED` — All agents finished successfully
- `FAILED` — One or more agents failed
- `ARCHIVED` — User deleted / hidden

**Indexes:**
- `userId` — B-tree (project listings)
- `status` — B-tree (dashboard filtering)
- Composite `(userId, status)` — common query

**Rules:**
- `onDelete: Cascade` on `user` relation — deleting a Clerk user wipes all their projects.
- `techStack` must validate against allowed enum values in application code.

### 3.3 AgentRun

One execution of a single agent within a project.

```prisma
model AgentRun {
  id          String    @id @default(cuid())
  projectId   String
  agentType   String?
  status      String    @default("IDLE")
  input       Json?
  output      Json?
  startedAt   DateTime?
  completedAt DateTime?
  errorMsg    String?
  tokenUsed   Int       @default(0)
  createdAt   DateTime  @default(now())

  project Project    @relation(fields: [projectId], references: [id], onDelete: Cascade)
  logs    AgentLog[]

  @@map("agent_runs")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `projectId` | String | FK → Project.id | Cascade delete |
| `agentType` | String? | — | SUPERVISOR, BACKEND, DATABASE, DEVOPS, FRONTEND, QA, REVIEWER, SECURITY, DOCUMENTATION |
| `status` | String | Default "IDLE" | IDLE, RUNNING, COMPLETED, FAILED |
| `input` | Json? | — | Prompt + context sent to LLM |
| `output` | Json? | — | Parsed files + text response |
| `startedAt` | DateTime? | — | Agent execution start |
| `completedAt` | DateTime? | — | Agent execution end |
| `errorMsg` | String? | — | Stack trace or LLM error |
| `tokenUsed` | Int | Default 0 | LLM tokens consumed (input + output) |

**Indexes:**
- `(projectId, agentType)` — Unique per agent per project? No — a project may have multiple runs of the same agent (chat retries). Use composite index for fast lookup.

**Rules:**
- `tokenUsed` feeds into `UsageLog` and plan enforcement.
- `input` and `output` may be large; consider truncating or storing in R2 for very long runs.

### 3.4 AgentLog

Structured log lines emitted by an agent during execution.

```prisma
model AgentLog {
  id         String   @id @default(cuid())
  agentRunId String
  level      String   @default("INFO")
  message    String?
  metadata   Json?
  timestamp  DateTime @default(now())

  agentRun AgentRun @relation(fields: [agentRunId], references: [id], onDelete: Cascade)

  @@map("agent_logs")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `agentRunId` | String | FK → AgentRun.id | Cascade delete |
| `level` | String | Default "INFO" | DEBUG, INFO, WARN, ERROR |
| `message` | String? | — | Human-readable log line |
| `metadata` | Json? | — | Arbitrary structured data (file path, line numbers) |
| `timestamp` | DateTime | Default now | Event time (may differ from `createdAt` if backfilled) |

**Indexes:**
- `(agentRunId, timestamp)` — B-tree for chronological retrieval

### 3.5 ProjectFile

A generated or user-edited file belonging to a project.

```prisma
model ProjectFile {
  id        String    @id @default(cuid())
  projectId String
  path      String
  content   String?
  language  String?
  createdBy String?
  version   Int       @default(1)
  createdAt DateTime  @default(now())
  updatedAt DateTime?

  project Project @relation(fields: [projectId], references: [id], onDelete: Cascade)

  @@map("project_files")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `projectId` | String | FK → Project.id | Cascade delete |
| `path` | String | — | Relative path: `src/app/page.tsx` |
| `content` | String? | — | Full file text; nullable for directory placeholders |
| `language` | String? | — | Monaco language ID: `typescript`, `prisma`, `dockerfile` |
| `createdBy` | String? | — | AgentType that generated this file, or `USER` for edits |
| `version` | Int | Default 1 | Incremented on every update |
| `updatedAt` | DateTime? | — | Last modification |

**Indexes:**
- `(projectId, path)` — Unique or composite? **Must be unique** per project. Add `@@unique([projectId, path])`.
- `(projectId, createdBy)` — Filter files by agent

**Rules:**
- `path` must use forward slashes; normalize on insert.
- `content` may be very large (> 100 KB). For files > 1 MB, consider storing content in R2 and keeping a pointer here.
- `version` increments atomically: `version: { increment: 1 }` in Prisma update.

### 3.6 ChatMessage

A message in the project chat panel.

```prisma
model ChatMessage {
  id          String   @id @default(cuid())
  projectId   String
  role        String?
  agentType   String?
  targetAgent String?
  model       String?
  content     String?
  metadata    Json?
  createdAt   DateTime @default(now())

  project Project @relation(fields: [projectId], references: [id], onDelete: Cascade)

  @@map("chat_messages")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `projectId` | String | FK → Project.id | Cascade delete |
| `role` | String? | — | USER, AGENT, SYSTEM |
| `agentType` | String? | — | If role=AGENT, which agent responded |
| `targetAgent` | String? | — | If user mentioned `@frontend`, routed to FRONTEND |
| `model` | String? | — | LLM model alias: `codellama`, `llama4`, etc. |
| `content` | String? | — | Message text; may include markdown |
| `metadata` | Json? | — | Token usage, latency, file edits |

**Indexes:**
- `(projectId, createdAt)` — B-tree for chronological pagination

**Rules:**
- Content limit: 10,000 characters. Truncate with ellipsis if exceeded.
- `targetAgent` is parsed from `@mention` syntax in application code.

### 3.9 UsageLog

Granular token consumption tracking for billing and plan enforcement.

```prisma
model UsageLog {
  id        String   @id @default(cuid())
  userId    String
  projectId String?
  agentType String?
  tokensIn  Int      @default(0)
  tokensOut Int      @default(0)
  cost      Int      @default(0)
  createdAt DateTime @default(now())

  user    User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  project Project? @relation(fields: [projectId], references: [id], onDelete: SetNull)

  @@map("usage_logs")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `userId` | String | FK → User.id | Cascade delete |
| `projectId` | String? | FK → Project.id | `SetNull` — keep usage even if project deleted |
| `agentType` | String? | — | Which agent consumed tokens |
| `tokensIn` | Int | Default 0 | Prompt tokens sent to LLM |
| `tokensOut` | Int | Default 0 | Completion tokens from LLM |
| `cost` | Int | Default 0 | Calculated cost in cents (future: per-model pricing) |

**Indexes:**
- `(userId, createdAt)` — Monthly usage aggregation
- `(userId, agentType, createdAt)` — Per-agent usage reports

### 3.10 ModelPreference

Per-project LLM model mapping.

```prisma
model ModelPreference {
  id          String   @id @default(cuid())
  projectId   String   @unique
  preferences Json     // { "SUPERVISOR": "llama4", "FRONTEND": "kimi", ... }
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  project Project @relation(fields: [projectId], references: [id], onDelete: Cascade)

  @@map("model_preferences")
}
```

| Field | Type | Constraints | Rationale |
|-------|------|-------------|-----------|
| `projectId` | String | Unique FK → Project.id | One record per project |
| `preferences` | Json | — | Key-value map: agentType → model alias |
| `updatedAt` | DateTime | `@updatedAt` | Auto-managed by Prisma |

**Rules:**
- Valid agent keys: all 9 agent types.
- Valid model values: aliases defined in `MODEL_ALIASES` (orchestrator `main.py`).
- Fallback: if key missing, use `OLLAMA_MODEL` env default.

## 5. Indexes & Performance

### 5.1 Existing / Recommended

| Table | Columns | Type | Purpose |
|-------|---------|------|---------|
| User | `clerkId` | UNIQUE | Auth lookup |
| User | `email` | UNIQUE | Contact + billing |
| Project | `userId` | B-tree | Dashboard listings |
| Project | `status` | B-tree | Filter by status |
| Project | `(userId, status)` | Composite | Dashboard with filters |
| ProjectFile | `(projectId, path)` | UNIQUE | Prevent duplicate paths |
| ProjectFile | `(projectId, createdBy)` | Composite | Filter by agent |
| ChatMessage | `(projectId, createdAt)` | Composite | Paginated chat history |
| AgentRun | `(projectId, agentType)` | Composite | Agent status lookup |
| AgentLog | `(agentRunId, timestamp)` | Composite | Chronological logs |
| UsageLog | `(userId, createdAt)` | Composite | Monthly billing aggregation |
| Subscription | `(userId, status)` | Composite | Active sub lookup |

### 5.2 Query Patterns

```sql
-- Dashboard: list user's projects
SELECT * FROM projects WHERE user_id = ? ORDER BY updated_at DESC;

-- Editor: load all files
SELECT * FROM project_files WHERE project_id = ? ORDER BY path;

-- Chat: paginated messages
SELECT * FROM chat_messages WHERE project_id = ? ORDER BY created_at DESC LIMIT 50 OFFSET ?;

-- Plan enforcement: monthly token usage
SELECT SUM(tokens_in + tokens_out) FROM usage_logs
WHERE user_id = ? AND created_at >= date_trunc('month', now());

-- Agent status: latest run per agent
SELECT DISTINCT ON (agent_type) * FROM agent_runs
WHERE project_id = ? ORDER BY agent_type, created_at DESC;
```

## 6. Migration Rules

1. **Never drop columns with data.** Rename + backfill instead.
2. **Add new columns as nullable first**, then backfill, then add `NOT NULL` in a follow-up migration.
3. **Enum fields are Strings** in Prisma (no native enum). Validate in application code.
4. **Json fields** must have TypeScript interfaces in `packages/shared-types` to ensure consistency.
5. **Cascade deletes** are acceptable for project-scoped data; never cascade from `User` to `UsageLog` if you need to retain billing records.
6. **Run `prisma migrate dev` locally**; `prisma migrate deploy` in CI/CD (K8s Job).
7. **Backwards compatibility:** API must handle both old and new schema shapes during rolling deployments.

## 7. Data Retention

| Data | Retention | Action |
|------|-----------|--------|
| Completed projects | 1 year | Archive to R2; soft-delete from DB |
| Failed projects | 90 days | Auto-purge after notification |
| Agent logs | 30 days | Bulk delete via cron |
| Build logs | 7 days | Aggressive purge |
| Chat messages | Forever | Keep for user reference |
| Usage logs | 2 years | Compliance + billing disputes |
